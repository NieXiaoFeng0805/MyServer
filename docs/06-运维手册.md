# 06 · 运维手册

## 1. 日常

```bash
cd /data/docker

docker compose ps                      # 状态
docker compose logs -f <service>       # 日志
docker stats --no-stream               # 实时占用
docker compose up -d <service>         # 只重建改动过的服务
docker compose pull && docker compose up -d   # 更新镜像
```

服务与端口见 [02-服务清单](02-服务清单.md)。

## 2. 健康检查顺序

1. `docker compose ps` —— 有没有容器在重启循环
2. `curl -I http://127.0.0.1:8096`（Jellyfin）、`:3000`（Homepage）、`:8080`（qB）
3. `curl -H 'Host: 192.168.1.88' http://127.0.0.1/` —— NPM 统一入口是否 200
4. `journalctl -u easytier -n 50`、`journalctl -u code-server -n 50`
5. `free -h`、`df -h / /data`、`uptime`

## 3. 备份

现在**没有备份**，这是当前最大风险。目标方案：

```bash
# 目标：/data 的配置类数据（约 10 MB），每日 03:30
rsync -a --delete \
  --link-dest=/run/media/nxl-server/Melon/backup/latest \
  /data/docker/ /data/alist/ /data/knowledge/ /data/photos/ \
  /run/media/nxl-server/Melon/backup/<日期>/
```

需要备份的：`/data/docker/*/config`、`/data/alist`、`/data/knowledge`、`/data/photos`、NPM 的 `database.sqlite` + `letsencrypt`。
不需要的：`/data/media`、`/data/downloads`（可重建，且会很大）。

`scripts/backup.sh` 只是骨架，Melon 插回来后再补全并加 systemd timer。

## 4. 恢复

```bash
# 单服务配置回滚（以 homepage 为例）
cp -a /path/to/backup/homepage-config/* /data/docker/homepage/config/
docker compose restart homepage

# NPM 配置回滚（改坏了最危险）
docker exec npm cp /data/database.sqlite.bak /data/database.sqlite
docker restart npm
```

> 动 NPM 之前**永远先** `docker exec npm cp /data/database.sqlite /data/database.sqlite.bak`。

## 5. 故障速查

| 现象 | 排查 |
|---|---|
| 统一入口 404，但容器都在 | 请求的 Host 不在 NPM `server_name` 里（见 docs/03） |
| Homepage 400 | `HOMEPAGE_ALLOWED_HOSTS` 缺当前 Host |
| 改了 compose 没变化 | 没 `up -d`，容器还是旧实例；`docker inspect` 看 `Memory`/`PortBindings` |
| 外网连不上 | EasyTier 是否在跑、是否有对端、本机是否在 `192.168.1.x` |
| 服务突然全断 | 机器休眠了（合盖/电池策略）；看 `journalctl -b \| grep -i suspend` |
| 磁盘满 | `docker system df`；`docker image prune -a`；`/var/lib/docker` 在 `/` 上 |
| QQ 掉线 | NapCat 被踢，重新扫码；`screen -r napcat` |
| 本地请求莫名卡住 | shell 里有代理变量，`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u all_proxy <cmd>` |

## 6. 安全基线

- `docker.sock` 只给必要容器；Portainer 是 rw（等同 root），Homepage 是 ro
- 网关密码只保护 `/portainer`、`/code`；其余靠各自认证
- 密钥集中放 `APIKey.txt`（600），不要散落在 compose 里
- 对外只暴露 22 / 80 / 81 / 443 / 11010 / 6881

## 7. 机器重启后

| 会自动起 | 需要手动/脚本 |
|---|---|
| Docker 全部容器（restart 策略） | NapCat（`screen -dmS napcat ...`） |
| code-server、EasyTier、mihomo? | AstrBot（`nohup .venv/bin/astrbot run &`） |
| dsh-web（user service） | 桌宠（如果用） |

> 你之前的 `MyLittleFish/脚本/watchdog.sh` 就是干这个的，建议挂 cron `@reboot`。
