> ✅ **WebUI 密码已固定 (2026-10-04)**: 密码为 APIKey.txt 中的 `<见 APIKey.txt>`。此前 qB 配置中**从未设置过密码**（qB 5.x 未设密码时每次重启都生成临时密码并打印在日志里），导致 APIKey.txt 记录失真、Homepage 面板反复登录失败触发防爆破封禁。修复方式：用日志中的临时密码经 API 登录后，`POST /api/v2/app/setPreferences`（注意：需 `json={...}` URL 编码表单格式，`application/json` 会 400）写入 `web_ui_password`，重启解封。

> ⚠️ **踩坑记录 (2026-10-04)**:
> ① **2026 版 NPM 没有默认管理员**（admin@example.com/changeme 失效）。Setup 界面通过未认证 `POST /api/users` 创建首个用户，密码放在 `auth: {type: "password", secret: "..."}` 嵌套字段里——只要已存在任意用户，未认证创建就会被 403，所以必须一次创建成功。此前手动创建的无密码用户曾把 API 锁死，最终删除 `database.sqlite` 重走官方 Setup 流程解决。
> ② **`forward_path: "/"` 会产生双斜杠**: nginx 把 proxy_pass 的 URI 与剩余路径直接拼接，`/code/login` 变成 `//login`。Portainer/qBittorrent 会归一化 `//` 所以无感，但 Jellyfin 和 code-server 不归一化（分别 404/401）。修复: `forward_path` 留空 + advanced_config 用 `rewrite ^/前缀(/.*)$ $1 break;` 剥离前缀。
> ③ **相对路径跳转**: code-server 的 302 使用 `./login` 相对 Location，浏览器会解析到错误位置。用 `proxy_redirect` 正则重写: `~^(\./)*login$` → `/code/login`。
> ④ 访问列表创建必须带 `items` 和 `clients` 数组，否则后端 500（`reading 'map'`）。
> ⑤ `POST /api/nginx/access-lists` 的 schema 允许 `items: [{username, password}]` 直接写入 basic auth 用户，无需走单独的 `/auth` 端点。
